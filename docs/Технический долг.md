# Технический долг MDS

Только отложенное сознательно. Каждая запись обязана нести два поля: **когда
возвращаться** (событие, а не дата — даты протухают, события наступают) и **цена
промедления**. Без них это не долг, а забытая задача.

Живые дефекты без починки живут не здесь, а в разделе «Открытые»
[[Журнал багов]].

## MDS-04b · Проверка origin вместо звёздочки

**Что отложено.** Заменить зашитую `*` (два места, см. [[CORS и origin'ы]]) на
проверку по списку разрешённых origin'ов.

**Почему отложено, а не сделано.** Список origin'ов выводится из реестра сайтов
платформы, а единого реестра нет. Реализовать проверку, которую нечем наполнить,
можно только двумя способами, и оба плохие: пустой список → пускаем всех
(fail-open, то есть та же звёздочка, но с видимостью защиты — хуже честной
звёздочки), либо пустой список → не пускаем никого (ломает локальную работу и
кабинет). Решение штаба: сначала реестр, потом проверка.

**Когда возвращаться.** Первое размещение MDS на машине, доступной снаружи —
**до** того, как она туда попадёт, а не после. Это событие, и оно наступит
раньше, чем появится реестр сайтов, поэтому проверять надо в момент подготовки
выкатки, а не ждать реестра.

**Цена промедления.** Локально — ноль: сервис слушает `localhost`, снаружи
недостижим. Снаружи — прямая и двойная: чужие потребители держат наши
socket.io-соединения и трафик фан-аута (ограничения на число клиентов нет), и
любой сайт может встроить наш поток к себе. Для платных категорий Twelve Data
второе — риск R-T5 из README (редистрибуция, условия в ToS провайдера). Пока
ключа Twelve Data нет, наружу идут только публичные данные Binance; с появлением
платного ключа цена перестаёт быть нулевой в тот же день.

**Чего эта отсрочка НЕ стоит.** Ключи провайдеров через CORS не утекают — они
остаются в env сервиса. И квоты провайдеров чужие потребители не жгут: расход у
обоих провайдеров константный и от числа подписчиков не зависит (проверено по
коду, разбор в [[CORS и origin'ы]]). Долг реальный, но он не про секреты и не про
деньги провайдера.

## MDS-05-д1 · Ключи провайдеров через служебную ручку

**Что отложено.** Р-047 предполагает ввод ключей в админке с передачей в MDS.
Ручка ключи **не принимает**; ключ задаётся окружением
(`MDS_PROVIDER_KEY_<ID>`), наружу отдаётся только факт наличия.

**Почему отложено, а не сделано.** Приём ключа означал бы секреты в открытом
JSON на диске, записываемые по общему секрету, в сервисе, у которого серверной
проверки доступа нет вовсе. Это больше экспозиции, чем проблема, которую
закрывает. Нужно решение владельца о месте хранения.

**Когда возвращаться.** Появление первого платного ключа **или** решение
владельца по хранилищу секретов — что наступит раньше. Второе важнее: без него
возвращаться не к чему.

**Цена промедления.** Сегодня нулевая: платных ключей нет, бесплатный Binance
ключа не требует. После появления платного ключа — организационная: смена
ключа требует доступа к окружению MDS и перезапуска, то есть участия команды
`deploy`, а не администратора в админке.

## MDS-05-д2 · Журнал изменений реестра не переживает рестарт

**Что отложено.** Журнал (`/v1/admin/audit`) — кольцо на 200 записей в памяти
плюс строки в stdout. Долговечного хранилища нет.

**Почему отложено.** MDS stateless по построению; заводить ему базу ради
журнала — отдельное решение штаба, а логи контейнера сейчас и так собираются.

**Когда возвращаться.** Первое из двух: реальный доступ администраторов к
ручке (не только нашей команды) **или** любое требование регуляторной
отчётности по смене источника цены.

**Цена промедления.** Прямая и неочевидная: смена источника — регуляторно
значимое событие, меняющее цену, по которой считались сделки. После рестарта
связь «скачок цены ↔ человек, который его вызвал» остаётся только в логах
контейнера, а они ротируются. **Выдавать текущий журнал за аудит нельзя.**

## MDS-05-д3 · Реестр лежит файлом, то есть у каждого экземпляра свой

**Что отложено.** Общего хранилища реестра нет: при двух и более экземплярах
MDS правка через ручку попадает **только в тот, который ответил**. Остальные
продолжают работать по старому реестру, и расхождение ничем себя не проявит.

**Почему отложено.** Экземпляр сегодня один. Делать распределённое состояние
под гипотетическое масштабирование — работа без заказчика.

**Когда возвращаться.** **До** запуска второго экземпляра MDS, не после. Это
то самое событие, которое наступит внезапно: горизонтальное масштабирование
обычно делают в день, когда стало тяжело.

**Цена промедления.** Пока экземпляр один — ноль. В день второго — разные
клиенты получают цены от разных источников, причём обе стороны «правы», а
снаружи это выглядит как расхождение котировок, а не как ошибка конфигурации.
Признак, по которому это диагностируется: `registry.version` в `/health` у
экземпляров разный.

## MDS-05-д4 · Запасной источник не подписан, пока не стал ведущим

**Что отложено.** Горячий резерв: запасной источник не получает символ, пока
ведущий жив. Переключение поэтому занимает время подписки на новый источник.

**Почему отложено.** Метрируемый источник (Twelve Data — кредиты) жёг бы
бюджет на данные, которые выбрасываются. Для источника с бесплатным потоком
это решение неверное — там резерв дешёвый.

**Когда возвращаться.** Появление второго бесплатного потокового источника на
те же символы.

**Цена промедления.** Секунды без цены при failover вместо мгновенного
переключения. Плюс упущенная польза: подписанный резерв позволил бы **мерить
расхождение цен** между источниками — а это единственный способ заметить, что
один из них врёт, и до сих пор у нас такой проверки нет вовсе.

## MDS-05-д5 · Смоук никто не гоняет — **частично закрыт 20.10, см. MDS-07-д1**

**Поправка 20.10.** CI заведён (`MDS-07`): контрактная половина смоука висит
на пуше в любую ветку и блокирует. ~~Но это не значит, что смоук гоняется:~~
прогон не исполняется — аккаунт заблокирован по биллингу (`B-008`), job не
стартует вовсе. Долг не закрыт, он **переехал**: с «CI нет» на «CI есть и не
работает». Это разные вещи, и вторая опаснее: по файлу в репозитории
выглядит закрытой.

**Что отложено.** Запуск смоука автоматикой.

~~**Почему отложено.** CI у зоны нет; заводить его — не наша задача.~~
**Почему отложено (20.10).** CI есть, не исполняется. См. `MDS-07-д1`.

**Когда возвращаться.** Появление CI у биржи, либо первая же следующая правка
формы ответов MDS.

**Цена промедления.** Измерена дважды: B-002 — смоук был мёртв полтора
месяца, B-007 — смоук честно печатал `FAIL` и прожил так месяц. **Красный,
которого не смотрят, равен зелёному.** Пока автоматики нет, смоук — ручной
обряд, и единственная защита состоит в том, что форму ответа и смоук правят
одним коммитом.

## MDS-07-д1 · CI заведён и ни разу не исполнился

**Что отложено.** Доказательство, что прогон доходит до шагов: контрактный
смоук печатает 11/11, живой по расписанию заводит issue на отказе.

**Почему отложено.** Не наша зона: аккаунт GitHub заблокирован по биллингу,
job не стартует. Проверено по API — у `Broker_CMS` 19 прогонов из 19 с той
же аннотацией с 24.07. Нужен владелец.

**Когда возвращаться.** В день разблокировки, не позже. Проверка одна:
есть ли у репозитория хоть один прогон, в котором выполнился хоть один шаг.

**Цена промедления.** Прямая и уже уплаченная: в нашей зоне автоматических
проверок нет вовсе. Ровно так смоук прожил месяц красным, а 19 красных
прогонов CI пролежали три месяца неоткрытыми. **Красный, которого не
смотрят, равен зелёному** — мы записали это правило про смоук и не
применили к самому CI.

~~И шире: ни одна проверка платформы не гоняется автоматически нигде.~~
**Неверно, см. поправку в `B-008`.** Блокировка только на аккаунте
`MyhaC1`; на `MyxaCe` Actions отработал 62 раза.
