# Локальный запуск MDS

Задача MDS-01. Главный вопрос был один: **обязан ли разработчик получить боевые
ключи провайдеров, чтобы работать с MDS.** Ответ — **нет**, и это проверено
прогонами ниже, а не выведено из кода.

Проверено 2026-09-03 на коммите `41c6c63`, Node v24.18.0, pnpm 9.15.9.

## Короткий путь

```bash
pnpm install
pnpm dev                      # :3003
curl localhost:3003/health
curl "localhost:3003/v1/quotes?symbols=BTCUSD"
```

`.env` не нужен вообще. Без `TWELVEDATA_API_KEY` сервис стартует, пишет в лог
`TWELVEDATA_API_KEY не задан — вселенная только Binance` и работает: крипта
Binance публична, ключ для неё не требуется. Инструменты Twelve Data
(форекс, металлы, акции, индексы) при этом выпадают из вселенной — их просто нет
в `/v1/instruments`, а не «есть, но без цены».

**Граница ключей соблюдена и не мешает работе.** Расширять доступ к секретам
ради локальной разработки не нужно никому.

## Что отдаёт в каждом состоянии

Четыре состояния прогнаны по отдельности: каталог и котировки — **разные**
источники, и ломаются они независимо. Каталог берётся из REST
`/api/v3/exchangeInfo` один раз на старте, котировки — из WS-стрима постоянно.

| Состояние | Как воспроизвести | `/health` | `catalog` | `/v1/quotes` |
| --- | --- | --- | --- | --- |
| Всё доступно | `pnpm dev` | `200 ok`, `binance: connected` | `binance-exchangeInfo`, 484 | живые цены |
| REST недоступен | `BINANCE_API_URL=http://127.0.0.1:9` | `200 ok`, `connected` | `static-fallback`, **12** | живые цены |
| WS недоступен | `BINANCE_WS_URL=ws://127.0.0.1:9` | `503 degraded`, `reconnecting` | `binance-exchangeInfo`, 484 | **пусто** `[]` |
| Ни того, ни другого | оба env выше | `503 degraded`, `reconnecting` | `static-fallback`, 12 | **пусто** `[]` |

Выводы, которые из этого следуют:

- **Фолбэк каталога действительно срабатывает**, а не только описан в README:
  `catalog.source` становится `static-fallback`, во вселенной ровно 12 мажоров
  (`BTCUSD ETHUSD SOLUSD XRPUSD BNBUSD ADAUSD DOGEUSD LTCUSD DOTUSD LINKUSD
  AVAXUSD TRXUSD`), при живом WS **котировки по ним настоящие**. Это рабочее
  состояние, а не аварийное.
- **Фолбэка котировок не существует и по смыслу быть не может.** Нет WS — нет
  цен: `/v1/instruments` отдаёт полную вселенную, `/v1/quotes` — пустой список.
  Витрина без цен. Отличить это от исправного сервиса легко: `/health` отдаёт
  **503** и `reconnecting`, список котировок пуст.
- Порядок отказов не смешивается: сломанный каталог не мешает котировкам,
  сломанный стрим не мешает каталогу.

## Режима фикстур нет

Искал: `grep -rniE "fixture|mock|фикстур|FAKE_|DEMO"` по `src/`, `scripts/`,
`.env.example`, `Dockerfile`, `docker-compose.yml` — пусто. Офлайн-режима,
который отдавал бы выдуманные цены, в сервисе нет, и это правильно: выдуманная
цена в котировочном сервисе неотличима от настоящей на стороне потребителя.

Ближайшее к «работе без сети» — фолбэк каталога выше: он отдаёт **список
инструментов** без сети, но никогда не отдаёт **цену** без провайдера.

## Опасное состояние: живой сокет без данных

Единственное состояние, в котором потребитель **не может** отличить исправный
сервис от сломанного. Воспроизведено поддельным провайдером, который принимает
`SUBSCRIBE`, отдаёт два тика и дальше молчит, **не закрывая соединение**
(half-open TCP: событие разрыва не приходит никогда).

Через 130 секунд после последнего тика:

```
/health   → 200 {"status":"ok","providers":[{"name":"binance",
                 "status":"connected","lastTickAt":<время первого тика>}]}
/v1/quotes → цены есть: BTCUSD=70000, ETHUSD=2000 (это данные подделки)
socket.io  → снапшот на subscribe приходит, дальше ТИШИНА
```

Что здесь не так, по пунктам:

- `/health` отдаёт **200 `ok`** и `connected`. Сервис уверен, что всё хорошо.
- `/v1/quotes` отдаёт **правдоподобные цены двухминутной давности**. Снапшот в
  памяти хаба (`src/hub.ts`, `last`) не протухает никогда — устаревшая цена
  живёт до рестарта.
- Потребитель по сокету получает снапшот и дальше **тишину**, которая
  **неотличима от тихого рынка**.
- Реконнекта не происходит: он висит на событиях `close`/`error`
  (`src/providers/binance.ts`), а их нет. Таймера тишины нет.

Единственный признак, по которому отказ вообще заметен снаружи, — поле `ts` в
котировке и `lastTickAt` в `/health`: они перестают расти. Ни один потребитель
не обязан это проверять, и на стороне MDS этого не проверяет никто.

Это ровно тот случай, ради которого записан урок **«отсутствие события не
является событием»**. Здесь он не абстрактный: воспроизводится за минуту,
подделка провайдера лежит в описании выше. Починка — таймер тишины в провайдере
и возраст снапшота в `/health` — относится к MDS-03, здесь только зафиксировано
и доказано.

## Docker

```bash
docker compose up -d --build      # :3003, БД нет — сервис stateless
```

`docker-compose.yml` пробрасывает только переменные Twelve Data. `PORT`,
`BATCH_MS`, `BINANCE_API_URL`, `BINANCE_WS_URL` в compose не проброшены — в
контейнере берутся дефолты из `src/config.ts`. Для локальной отладки отказов
(таблица выше) используйте `pnpm dev`, а не compose.

## Что нашлось попутно и относится к другим задачам

- **`CORS_ORIGINS` в сервисе не существует.** MDS-04 исходит из того, что список
  origin'ов ведётся здесь руками. Фактически в коде зашита звёздочка:
  `Access-Control-Allow-Origin: *` (`src/index.ts:64`) и
  `cors: { origin: '*' }` у socket.io (`src/hub.ts:20`). Ни переменной
  окружения, ни списка, ни проверки origin нет — запрос с любого origin
  проходит. Пункт приёмки MDS-04 «проверено вживую, что запрос с чужого origin
  отклоняется» в текущем коде выполнить нельзя: отклонять нечем. Это отдельная
  задача, здесь только факт.
- Ключей Twelve Data нет, поэтому все прогоны выше — на вселенной только
  Binance. Поведение сервиса при отвале одного провайдера из двух не проверено
  ничем (MDS-03).
