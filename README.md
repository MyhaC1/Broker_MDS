# Broker MDS · Market Data Service

Единый сервис котировок платформы брокера (ADR-024 сайта). Мотив: **все API-ключи провайдеров живут только здесь** (1 ключ на платформу вместо ключа на каждый сайт; лимиты провайдера тратятся один раз — MDS мультиплексирует).

**Stateless**: БД нет, последние котировки в памяти и восстанавливаются от провайдера за секунды после рестарта.

## Потребители и контракты

- **Сайты** — socket.io, контракт `FeedDriver` сайта дословно: клиент шлёт `subscribe`/`unsubscribe` (список канонических символов), сервер — `quotes:batch` (`Quote[]`, батч ~250 мс, на subscribe сразу снапшот). Подключение сайта = смена `NEXT_PUBLIC_WS_URL` на MDS.
- **Терминал** (по плану ADR-024) — меняет upstream с прямого Binance на MDS; символы уже канонические, маппинг у терминала снимается.
- **REST**: `GET /health` · `GET /v1/instruments` (что реально стримим; каждый инструмент несёт относительный путь `icon`) · `GET /v1/quotes?symbols=BTCUSD,ETHUSD` (снапшот) · `GET /icons/<SYMBOL>.svg` (иконки монет, набор MIT cryptocurrency-icons в `public/icons/`).

## Источники

- **Вселенная инструментов — статическая, в самом MDS** (`src/catalog.ts`): источник правды о том, что реально стримится, — сам сервис. Зависимости от CMS нет (цикл CMS→MDS→CMS разорван); наоборот, админка CMS выбирает инструменты сайта из `GET /v1/instruments` MDS. Канонический символ платформы (`BTCUSD`) — единственный, который видят потребители.
- **Провайдер MVP — Binance** (публичные стримы, ключ не нужен): combined `@ticker`, reconnect с backoff (разрывы каждые 24 ч у Binance штатны). Маппинг `BTCUSD → btcusdt` — в каталоге.
- Прочие категории (forex/металлы/индексы/акции) — с платными провайдерами; **до покупки ключа проверить ToS на редистрибуцию** (риск R-T5 платформы).

## Запуск

```bash
pnpm install
pnpm dev            # :3003, вселенная инструментов статическая
# либо в Docker:
docker compose up -d --build
```

Проверка: `curl localhost:3003/health` · `curl "localhost:3003/v1/quotes?symbols=BTCUSD"`.
